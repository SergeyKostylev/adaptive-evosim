# PROJECT_SPEC.md — Adaptive EvoSim

**Проєкт:** Еволюція плаваючих істот у 2D в'язкому середовищі (генетичний алгоритм + спрощена гідродинаміка).
**Контекст:** магістерське наукове дослідження (Artificial Life / Computational Intelligence).
**Статус документа:** єдине джерело істини для реалізації. Інші моделі (Claude Code) пишуть код строго за цим документом, без додумування математики чи контрактів.

---

## 0. Огляд та ключові рішення

Істоти (creatures) з рухомими кінцівками еволюціонують, щоб навчитися плавати у в'язкому середовищі та уникати хижака, виявляючи його сенсорами заздалегідь.

Принципові рішення (зафіксовані, не обговорюються при реалізації):

| # | Рішення | Значення |
|---|---------|----------|
| R1 | Середовище | **Все поле — суцільна в'язка рідина.** Немає рівня води, поверхні, берега. Гравітація `g = 0` (нейтральна плавучість). «Водність» реалізується виключно силами опору (drag/lift) та демпфуванням. |
| R2 | Фізичний рушій | Pymunk (Chipmunk2D). Крок фізики фіксований: `DT = 1/120 c`. |
| R3 | Контролер | MLP фіксованої топології; еволюціонують лише ваги/біаси (neuroevolution of weights). |
| R4 | Геном | Плоский вектор `float32` = усі ваги та біаси MLP. |
| R5 | Режими | Headless (без рендера, максимальна швидкість, мультипроцесна оцінка популяції) — основний; Live (60 fps через WebSocket) — перегляд найкращої особини або живого тренування. |
| R6 | Хижаки | Кінематичні агенти (скриптовий FSM), не еволюціонують. У сцені їх може бути кілька (до 8); сенсори та фітнес працюють із **найближчим** із них. |
| R7 | Детермінізм | Увесь прогін відтворюваний за `seed` (NumPy Generator + фіксований DT + фіксований порядок оцінки). |
| R8 | Frontend | Чистий HTML5/CSS/JS (ES-модулі, без фреймворків), Canvas 2D, Chart.js з CDN, темна тема, процедурна графіка без растрових зображень. |

Глосарій:

- **Сегмент** — тверда ланка кінцівки (прямокутник/капсула).
- **Суглоб** — `PivotJoint + RotaryLimitJoint + SimpleMotor` між двома ланками.
- **Аура** — зона небезпеки навколо хижака радіусом `R_aura`; потрапляння в неї штрафується, дотик до тіла хижака (`R_catch`) — смерть.
- **Епізод** — одна симуляція однієї особини тривалістю `T_episode` сим-секунд.
- **Покоління** — повна оцінка популяції + селекція/схрещування/мутація.

### 1.2 Відповідальність модулів

- **`hydro.py`** — лише формули (розділ 2): чисті функції `segment_fluid_force(...)`, легко юніт-тестуються без фізичного рушія.
- **`physics.py`** — володіє `pymunk.Space`; на кожному кроці викликає `hydro` для кожного сегмента кожного тіла та застосовує сили через `body.apply_force_at_world_point`.
- **`world.py`** — фасад одного епізоду: `World(creature_cfg, env_cfg, genome, seed)`, метод `step()` (фізика + сенсори + мозок + хижак + фітнес-акумуляція), властивості `alive`, `t`, `snapshot()` → дані для FramePacket.
- **`evaluator.py`** — головний headless-шлях: отримує список геномів, розганяє по процесах (`multiprocessing`, по одному `World` на геном), повертає масив фітнесів та компонентів фітнесу. Жодного рендера, жодного sleep.
- **`sim_manager.py`** — єдиний stateful-сервіс застосунку. Тримає поточний прогін ГА у фоновому потоці, публікує події (`generation_done`, `state_changed`) у asyncio-черги для WebSocket.
- **Frontend** не містить фізики чи логіки еволюції — тільки редагування конфігів (JSON), відображення кадрів та графіків.

## 2. Фізична модель в'язкого середовища

### 2.1 Загальні параметри середовища

| Параметр | Символ | Дефолт | Опис |
|---|---|---|---|
| Густина рідини | `rho` | `1.0` | умовні одиниці, масштабує всі гідросили |
| Гравітація | `g` | `(0, 0)` | нейтральна плавучість, фіксовано (R1) |
| Глобальне лінійне демпфування | `space.damping` | `0.98` | за крок; «фонова» в'язкість, страхує від вічного дрейфу |
| Крок фізики | `DT` | `1/120 c` | фіксований; керування (мозок) — кожні `CONTROL_EVERY = 6` кроків (20 Гц) |
| Нормальний коеф. опору | `C_d_perp` | `2.0` | пластина поперек потоку |
| Тангенційний коеф. опору | `C_d_par` | `0.1` | ковзання вздовж сегмента |
| Коеф. підйомної сили | `C_l` | `0.5` | опційно, `0` вимикає lift |
| Ліміт сили на точку | `F_max` | `500` | кламп для числової стабільності |
| Точок вибірки на сегмент | `N_s` | `3` | рівномірно вздовж осі сегмента |

**Ключовий механізм плавання:** анізотропія опору `C_d_perp ≫ C_d_par`. Сегмент, що рухається поперек своєї осі, гальмується в ~20 разів сильніше, ніж уздовж. Саме це дозволяє ундуляційним і весловим рухам створювати тягу: швидкий мах «плазом» відштовхує середовище, повернення «руба» майже не гальмує.

### 2.2 Сили на сегмент (точна математика, `hydro.py`)

Кожен сегмент — тонкий прямокутник довжиною `L` (вздовж локальної осі) та шириною `w`. Рідина нерухома, тому відносна швидкість точки = швидкість точки тіла.

Для сегмента беремо `N_s` точок вибірки `p_k` на осі сегмента (при `N_s = 3`: центри третин). Кожній точці відповідає ефективна довжина `L_k = L / N_s`.

Для кожної точки `p_k` (усе у світових координатах):

1. Швидкість точки: `v = body.velocity_at_world_point(p_k)`; якщо `|v| < 1e-6` — сили немає.
2. Одиничний вектор осі сегмента `t̂` (із кута тіла), нормаль `n̂ = perp(t̂)`.
3. Розкладання: `v_t = (v·t̂) t̂`, `v_n = (v·n̂) n̂`.
4. **Опір (drag)**, квадратичний, площа на одиницю «глибини» `A_k = L_k`:

   ```
   F_drag = −0.5 · rho · C_d_perp · L_k · |v_n| · v_n
            −0.5 · rho · C_d_par  · L_k · |v_t| · v_t
   ```

5. **Підйомна сила (lift)**, спрощена модель тонкої пластини. Кут атаки `α` — кут між `v` та `t̂`:

   ```
   sinα = (v·n̂)/|v|,  cosα = (v·t̂)/|v|
   F_lift = 0.5 · rho · C_l · L_k · |v|² · (2·sinα·cosα) · l̂
   ```

   де `l̂` — одиничний вектор, перпендикулярний до `v`, зі знаком, що повертає потік у бік від пластини: `l̂ = normalize(perp(v)) · sign(sinα·cosα)` (при `C_l = 0` блок вимкнено).

6. Сумарна сила точки: `F_k = clamp_magnitude(F_drag + F_lift, F_max)`.
7. Застосування: `body.apply_force_at_world_point(F_k, p_k)`.

Оскільки сили прикладаються в кількох точках уздовж сегмента з локальними швидкостями, **обертальний опір виникає автоматично** — окремий момент в'язкого тертя не потрібен. (Довідково, еквівалентний момент для стрижня, що обертається навколо центра: `τ = rho·C_d_perp·w·|ω|·ω·L⁴/64` — використовується лише в юніт-тесті `test_hydro.py` як перевірка збіжності при `N_s → 7`.)

Кругле центральне тіло (радіус `r`) отримує ізотропний опір у центрі мас:

```
F_body = −0.5 · rho · C_d_body · (2r) · |v| · v,   C_d_body = 1.2
τ_body = −rho · C_d_body · r⁴ · |ω| · ω              (обертальне демпфування диска)
```

### 2.3 Стабільність

- Усі гідросили обчислюються зі швидкостей **на початку кроку**, застосовуються, потім `space.step(DT)`.
- Кламп `F_max` на кожну точку та кламп `|v| ≤ V_MAX = 50` на тіла (жорстке обрізання швидкості після кроку) — захист від вибуху при поганих геномах.
- Маси: мінімальна маса сегмента `0.1`, момент інерції — з `pymunk.moment_for_box`.

## 3. Модель істоти (морфологія)

Істота = центральне тіло + до `MAX_LIMBS = 6` кінцівок; кінцівка = ланцюжок до `MAX_SEGMENTS = 4` сегментів.

- **Центральне тіло:** коло радіуса `r ∈ [0.3, 1.5]` або опуклий полігон (3–8 вершин), густина `density ∈ [0.5, 3.0]`.
- **Сегмент:** прямокутник `L ∈ [0.3, 2.0]`, `w ∈ [0.05, 0.4]`, густина як у тіла або власна.
- **Суглоб** між ланкою `i−1` та `i`:
  - `PivotJoint` у точці кріплення (кінець попередньої ланки);
  - `RotaryLimitJoint` з лімітами `[angle_min, angle_max]`, `angle_min ∈ [−2.5, 0]`, `angle_max ∈ [0, 2.5]` рад відносно нейтралі;
  - `SimpleMotor` з `max_force = motor_torque ∈ [10, 500]`; **керований параметр — `motor.rate`** (цільова кутова швидкість).
- Кінцівка кріпиться до тіла у точці, заданій кутом `attach_angle` на периметрі тіла, з базовою орієнтацією `rest_angle`.
- Колізії між ланками однієї істоти вимкнені (`ShapeFilter(group=creature_id)`).
- Категорії колізій: `CAT_CREATURE = 0b001`, `CAT_OBSTACLE = 0b010`, `CAT_PREDATOR = 0b100`.

Керування: на кожному control-тику (20 Гц) вихід мережі `u_j ∈ [−1, 1]` для суглоба `j` перетворюється:

```
motor_j.rate = u_j · OMEGA_MAX,   OMEGA_MAX = 6.0 рад/с
```

Повна JSON-схема істоти — розділ 9.1.

## 4. Сенсорна модель

Вектор входів мережі будується у **локальній системі координат істоти** (інваріантність до положення/повороту світу). Три групи:

### 4.1 Радар (raycast-промені)

- `N_rays = 12` променів рівномірно по колу 360° від центра тіла, дальність `R_ray = 12.0`.
- Кожен промінь — `space.segment_query_first` з маскою `CAT_OBSTACLE | CAT_PREDATOR` (власні шейпи виключені фільтром).
- На промінь — **2 канали**:
  - `d_obs = 1 − dist/R_ray`, якщо влучив у перешкоду/стіну, інакше `0`;
  - `d_pred = 1 − dist/R_ray`, якщо влучив у тіло хижака, інакше `0`.

### 4.2 Аура хижака (distance-field, «передчуття»)

Істота відчуває ауру навіть крізь перешкоди (біологічна аналогія — хеморецепція/бічна лінія):

Якщо хижаків кілька, береться **найближчий** (максимальна аура):

```
dist  = min_p |pos_creature − pos_p|          # p — хижаки зі сцени
aura  = clamp(1 − dist / R_aura_sense, 0, 1)        # R_aura_sense = 1.5 · R_aura
bear  = кут на хижака в локальних координатах істоти
входи: [aura, aura·sin(bear), aura·cos(bear)]        # 3 канали; (0,0,0) якщо поза зоною
```

### 4.3 Пропріоцепція

- На кожен суглоб: `[sin(θ_j), cos(θ_j), ω_j / OMEGA_MAX]` — 3 канали (θ — поточний кут суглоба відносно нейтралі, нормалізований лімітами).
- Тіло: локальна лінійна швидкість `[v_x, v_y]/V_NORM` (`V_NORM = 5`), кутова швидкість `ω/OMEGA_MAX`, орієнтація `[sin(φ), cos(φ)]` — 5 каналів.
- Осцилятор (центральний генератор ритму, допомагає еволюції знайти періодичний хід): `[sin(2π f t), cos(2π f t)]`, `f = 1.0 Гц` — 2 канали.

### 4.4 Розмір входу

```
N_in = N_rays·2 + 3 + N_joints·3 + 5 + 2 = 24 + 3 + 3·N_joints + 7
```

Приклад: істота з 2 кінцівками × 2 сегменти (4 суглоби) → `N_in = 46`.

## 5. Контролер (мозок)

MLP фіксованої топології, обчислення на NumPy:

```
Вхід:   x ∈ R^{N_in}
Шар 1:  h1 = tanh(W1·x + b1),  W1: [16 × N_in]
Шар 2:  h2 = tanh(W2·h1 + b2), W2: [16 × 16]
Вихід:  u  = tanh(W3·h2 + b3), W3: [N_joints × 16],  u ∈ [−1,1]^{N_joints}
```

- Розмір геному: `G = 16·N_in + 16 + 16·16 + 16 + N_joints·16 + N_joints`.
- Виходи застосовуються до моторів (розділ 3) кожні `CONTROL_EVERY = 6` фізичних кроків; між тиками `motor.rate` утримується.
- Мережа **детермінована**, без внутрішнього стану (вся «пам'ять» — осцилятор і фізика).

## 6. Геном та генетичний алгоритм

### 6.1 Геном

- `genome: np.ndarray[float32]` довжини `G` — конкатенація `[W1.flat, b1, W2.flat, b2, W3.flat, b3]` саме в такому порядку.
- Ініціалізація: `N(0, 0.5)` для ваг, `0` для біасів.
- Серіалізація: JSON `{ "creature_hash": "...", "n_in": 46, "n_joints": 4, "weights": [ ... ] }` (`creature_hash` = SHA-256 від канонічного JSON морфології — захист від завантаження геному під чужу морфологію).

### 6.2 Цикл ГА (`ga.py`)

| Параметр | Дефолт |
|---|---|
| Популяція `P` | 100 |
| Поколінь `N_gen` | 200 |
| Елітизм | 2 найкращі копіюються без змін |
| Селекція | турнірна, `k = 3`, з поверненням |
| Схрещування | uniform, `p_swap = 0.5` на ген; ймовірність кросовера `p_cx = 0.9`, інакше клон батька |
| Мутація | гаусова: кожен ген з ймовірністю `p_mut = 0.05` отримує `+N(0, σ)`, `σ = 0.15`; після мутації кламп у `[−5, 5]` |
| Епізодів на особину `E` | 2 (різні сіди позицій хижака), фітнес = середнє |
| Тривалість епізоду `T_episode` | 30 сим-секунд (3600 кроків) |

Псевдокод покоління:

```
fitnesses = evaluator.evaluate(population, creature_cfg, env_cfg, seeds[gen])
stats = {best, avg, std, diversity}            # diversity = середня попарна L2 між 20 випадковими геномами / sqrt(G)
new_pop = top2(population)                     # елітизм
while len(new_pop) < P:
    a, b = tournament(k=3), tournament(k=3)
    child = uniform_crossover(a, b) if rng.random() < p_cx else a.copy()
    mutate(child)                              # in-place, гаусова
    new_pop.append(child)
population = new_pop
```

- **Відтворюваність:** один `np.random.Generator(PCG64(seed))` на прогін; сіди епізодів: `seed_episode = hash(run_seed, gen, individual_idx, episode_idx)` через `np.random.SeedSequence.spawn`.
- **Паралелізм:** `evaluator` ділить популяцію на чанки по процесах (`N_WORKERS = os.cpu_count() − 1`); кожен воркер будує власний `World` на епізод. Результат — масив `[P × E]` фітнесів + покомпонентний розклад (для аналітики).

## 7. Фітнес-функція

Обчислюється `FitnessAccumulator`-ом під час епізоду, фіналізується в кінці. Мета — виживання + ефективне плавання, з анти-чит механізмами.

### 7.1 Формула

```
F = w_surv·S + w_dist·D − w_dang·G_aura − w_coll·C − w_pass·Pas − w_enrg·E_n
```

| Компонент | Формула | Дефолтна вага | Анти-чит призначення |
|---|---|---|---|
| Виживання `S` | `t_alive / T_episode ∈ [0,1]` | `w_surv = 3.0` | головна ціль |
| Дистанція `D` | `min(‖pos(t_end) − pos(0)‖ / D_norm, 1)`, `D_norm = 20` | `w_dist = 1.5` | **чисте зміщення**, не шлях — виключає нагороду за кружляння на місці |
| Небезпека `G_aura` | `(1/T_episode)·Σ_t aura(t)·DT`, де `aura(t) = max_p clamp(1 − dist_p/R_aura_p, 0, 1)` по всіх хижаках | `w_dang = 2.0` | інтеграл перебування в аурі; вчить триматися далі, а не «виживати впритул» |
| Колізії `C` | `min(n_hits/10, 1)`, `n_hits` — кількість контактів істота↔перешкода (collision handler, дебаунс 0.25 с на пару) | `w_coll = 1.0` | карає таранити перешкоди |
| Пасивність `Pas` | `max(0, 1 − v̄/v_min)`, `v̄` — середня швидкість центра за епізод, `v_min = 0.3` | `w_pass = 1.0` | істота, що «лежить», отримує повний штраф |
| Енергія `E_n` | `(1/T_episode)·Σ_t Σ_j |u_j(t)|·DT / N_joints ∈ [0,1]` | `w_enrg = 0.3` | м'який штраф за безглузде смикання моторами |

### 7.2 Термінальні події

- **Спіймання** (`dist(creature, p) < R_catch_p` для будь-якого хижака `p` або контакт шейпів): епізод завершується, `t_alive` фіксується. Додатковий разовий штраф **не** нараховується — втрата `S` і `D` вже достатня (уникаємо подвійного покарання, яке глушить градієнт ранньої еволюції).
- **Вихід за межі світу:** світ обмежений статичними стінами (прямокутник `W_world × H_world = 60 × 40`), стіни = перешкоди (`C` штрафує), вилетіти неможливо.

### 7.3 Усереднення

Фітнес особини = середнє по `E = 2` епізодах з різними стартовими позиціями/фазами патруля хижака. Це карає оверфіт під конкретну траєкторію хижака.

## 8. Хижак та перешкоди

### 8.1 Хижаки (`predator.py`)

Кінематичні тіла (`pymunk.Body.KINEMATIC`), форма — коло радіуса `r_body`
(дефолт `0.8`, діапазон `[0.2, 3.0]`; редагується в конструкторі). Дотик до тіла
теж означає спіймання, тож ефективний радіус спіймання — `max(r_catch, r_body)`.
Сцена містить **список** хижаків (0–8), кожен зі своїм маршрутом і радіусами;
FSM нижче виконується для кожного незалежно. Хижаки не взаємодіють між собою.

| Параметр | Дефолт |
|---|---|
| Радіус тіла | `r_body = 0.8` (діапазон `[0.2, 3.0]`) |
| Маршрут патруля | список waypoint-ів (≥2), швидкість `v_patrol = 2.0` |
| Радіус виявлення | `R_detect = 8.0` (пряма видимість не потрібна) |
| Швидкість погоні | `v_chase = 3.5` (трохи вище крейсерської швидкості еволюціонованих істот) |
| Радіус аури | `R_aura = 5.0` (зона штрафу, розділ 7) |
| Радіус спіймання | `R_catch = 1.0` |
| Межа погоні | `T_giveup = 6 c` без скорочення дистанції → RETURN |

FSM:

```
PATROL: рух по waypoint-ах по колу (лінійна інтерполяція, поворот до напрямку руху).
        if dist(creature) < R_detect → CHASE
CHASE:  velocity = v_chase · normalize(pos_creature − pos_pred); таймер «без прогресу».
        if dist > R_detect·1.5 or таймер > T_giveup → RETURN
RETURN: рух до найближчого waypoint-а зі швидкістю v_patrol → PATROL
```

Рух — виключно через `body.velocity` (кінематика), гідросили на хижака не діють.

### 8.2 Перешкоди (`obstacles.py`)

- **Статичні:** опуклі полігони (3–10 вершин) або кола, `body_type = STATIC`.
- **Кінематичні (рухомі):** полігон, що рухається туди-назад між двома точками (`speed`, `phase`) або обертається (`angular_velocity`). Рух синусоїдальний: `pos(t) = lerp(p1, p2, 0.5 + 0.5·sin(2π t/period + phase))`.
- Перешкоди не взаємодіють з хижаком (фільтр), взаємодіють з істотою (колізія → компонент `C`).

### 9.1 `CreatureConfig`

```json
  "name": "swimmer-v1",

    "shape": "circle",

    "vertices": null,
```

**`spawns`** (0–16) — місця появи істот у сцені. `creature: null` (або `"current"`)

live-перегляду. Еволюціонує завжди морфологія з `ExperimentConfig.creature`, її старт
задає `spawns[0]`; якщо список порожній — старт у центрі світу.

приймається для сумісності зі збереженими сценами й згортається у `predators[0]`;
у відповідях і дампах воно не з'являється.

у підказках `title`, щоб UI лишався звірюваним зі схемами розділу 9. Кутові величини
показуються у **градусах** (внутрішнє представлення — радіани, як у схемах).

Моноширинний шрифт для чисел (`ui-monospace`), системний sans для решти. Жодних растрових картинок: усе — Canvas/CSS. Chart.js підключається з cdnjs конкретною версією.

### 10.2 Вкладки SPA

**Editor (конструктор):**
- Канвас-сцена зі світом (сітка, межі) + панель інструментів: *Істота / Хижак / Сцена* — рівно три сутності системи. Режими **ізольовані**: у «Істоті» на полотні лише морфологія, у «Хижаку» — лише він сам із радіусами й векторами швидкостей, у «Сцені» — світ. Сцена має підрежими *Перешкоди / Маршрути / Точки появи*. Поєднуються сутності на вкладці «Симуляція».
- Тіло: вибір circle/polygon, слайдери radius/density; полігон — кліки по канвасу (3–8 вершин, автоопуклість).
- Кінцівка: клік по вільному периметру тіла = нова точка кріплення; клік по наявній точці — вибір кінцівки, `Ctrl/⌘ + клік` — **мультивибір** (у списку також `Shift + клік` = діапазон). Правки форми застосовуються до всіх вибраних кінцівок одночасно (`attach_angle` — як зсув, щоб вони не злилися в одну точку). Форма сегмента: length, width, density, angle_min, angle_max, motor_torque; кнопка «+ сегмент» (до 4).
- Вибрана кінцівка підсвічується (яскравіша заливка, обведення, світіння, маркер `L{i}`), а для кожного її суглоба на канвасі малюється **сектор допустимих кутів** `[angle_min, angle_max]` з підписом у градусах, «спицями» крайніх положень і привидами сегмента в цих положеннях.
- Перешкоди: статичний полігон/коло малюється кліками; рухомий — додатково дві точки `p1`,`p2` + period.
- Хижак (окремий режим): слайдери `r_body, v_patrol, v_chase, r_detect, r_aura, r_catch` (біля радіусів аури й тіла показується діаметр), прев'ю з концентричними радіусами та стрілками швидкостей; збереження в бібліотеку хижаків. Маршруту тут немає.
- Сцена → Маршрути: список маршрутів (до 8), для кожного вибирається хижак із бібліотеки (його параметри копіюються у запис) або лишаються власні; клік по полотну додає точку **вибраному** маршруту.
- Сцена → Точки появи: клік ставить старт популяції (до 16), у кожної точки є поворот і підпис. радіуси відображаються концентричними колами (`--danger` з прозорістю).
- Бібліотека істот: випадаючий список **над полотном** — мініатюра морфології (процедурний рендер тієї самої геометрії) і назва; клік завантажує істоту в редактор, `✕` видаляє. Там же збереження поточної істоти під назвою та експорт/імпорт JSON. Редактор завжди працює з **однією** істотою; бібліотека — спосіб перемикатися між ними.
- Варіанти сцени: збереження поточної сцени під назвою та завантаження назад (`/api/editor/presets`).
- Кнопки: **Validate** (`POST /api/creature/validate`, показ `genome_size`), **Save JSON** (download), **Load JSON** (file input), **Use in Experiment**.

**Simulation:**
- **Перегляд сцени** займає основну площу вкладки: вибрана істота малюється на кожній точці появи, хижаки — на початку своїх маршрутів із радіусами й аурою, перешкоди та межі світу. Камера: перетягування мишею, масштаб колесом, кнопка «Вписати». Той самий `renderer.js` з етапу 2 показуватиме тут живі кадри `FramePacket`.
- Під канвасом — рядок перевірок, які видно оком, але не видно в JSON: старт усередині аури хижака, старт поза межами світу, порожня сцена, відкинуті незавершені маршрути.
- Панель «Що буде еволюціонувати»: `n_joints`, `n_in`, `genome_size` вибраної істоти та вартість покоління в сим-секундах (`population × episodes × episode_seconds`).
- `ExperimentConfig` лишається доступним як згорнутий JSON із кнопкою копіювання — це тіло запуску (§9.4) і знімок прогону (§11).
- Складові експерименту: три списки — істота (бібліотека), сцена (варіанти) і хижак (бібліотека). Вибраний хижак застосовується до маршрутів без власного `preset`; маршрути, коротші за 2 точки, відкидаються з попередженням. У конфіг потрапляють **копії**, а не назви (§11).
- Форма параметрів ГА + ваг фітнесу (значення з 9.3), кнопки Start / Pause / Resume / Stop.
- Перемикач **Headless ↔ Live**: headless — лише метрики; live — `POST /api/preview {source:"live_training"}` і канвас-рендер поточного найкращого в процесі тренування. Вимкнення live не зупиняє навчання.
- Канвас-рендер FramePacket: тіло та сегменти (`--accent`, обведення + заливка з прозорістю), промені сенсорів (`--accent-2`, у хижака — `--danger`), аура хижака — радіальний градієнт `--danger`→transparent, перешкоди — `--warn` контур. Камера: слідкує за істотою, масштаб колесом миші.
- HUD поверх канваса: Gen, Episode t, стан хижака, running fitness з розкладом компонентів.

**Analytics:**
- Chart.js line-charts у реальному часі з `/ws/metrics`: (1) Best + Avg Fitness по поколіннях; (2) Population Diversity; (3) stacked-компоненти фітнесу найкращої особини.
- Таблиця прогонів з `/api/experiments`; кнопки **Export CSV**, **Export PDF (charts)**, **Download best genome**.

### 10.3 `ws.js` — правила клієнта

- Автоперепідключення з експоненційною затримкою (0.5 → 8 с).
- Рендер по `requestAnimationFrame`; зберігається лише останній отриманий кадр (стара черга скидається).

## 11. Збереження експериментів (`experiment_store.py`)

```
experiments/editor/last_session.json  # стан конструктора між сеансами (9.4)
experiments/editor/creatures/*.json   # бібліотека істот
```

- Графіки для дипломної: matplotlib, `dpi=200`, підписи осей українською, збереження у PNG та PDF (векторний — для LaTeX/Word).

## 12. Docker

**`docker-compose.yml`** (запуск: `docker compose up --build`):

```yaml
services:
  backend:
    build: { context: ., dockerfile: docker/backend.Dockerfile }
    volumes:
      - ./experiments:/app/experiments
    environment:
      - WORKERS_EVAL=0        # 0 = auto (cpu_count - 1)
    expose: ["8000"]
  frontend:
    build: { context: ., dockerfile: docker/frontend.Dockerfile }
    ports: ["8080:80"]
    depends_on: [backend]
```

- **backend.Dockerfile:** `python:3.12-slim`, інсталяція через `pip install .` з `pyproject.toml`, запуск `uvicorn app.main:app --host 0.0.0.0 --port 8000` (один uvicorn-воркер; паралелізм — усередині evaluator).
- **frontend.Dockerfile:** `nginx:alpine`, копіює `frontend/` у `/usr/share/nginx/html`, `nginx.conf` проксить `location /api` та `location /ws` (з `Upgrade`-заголовками) на `backend:8000`.
- Для локальної розробки без Docker: `uvicorn app.main:app --reload` + FastAPI `StaticFiles` на `frontend/` (fallback-режим, вмикається env-змінною `SERVE_STATIC=1`).

## 15. Тестування та якість

- **Юніт:** pytest; математика (`hydro`, `fitness`, `genome`) — без Pymunk, де можливо, на чистому NumPy.
- **Інтеграційні:** короткі епізоди (2–3 с) повного `World` — відсутність NaN, виконання інваріантів (`|v| ≤ V_MAX`, енергія не вибухає).
- **Контрактні:** `test_api_contracts.py` через `fastapi.testclient` — кожен ендпоінт відповідає схемам розділу 9.
- **Інваріант відтворюваності** (най важливіший для наукової роботи): фіксований seed → ідентичні результати; тест ганяється в CI-режимі локально перед кожним milestone-DoD.
