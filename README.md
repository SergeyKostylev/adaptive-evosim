# Adaptive EvoSim

Еволюція плаваючих істот у 2D в'язкому середовищі: генетичний алгоритм +
спрощена гідродинаміка. Магістерське наукове дослідження.

- `PROJECT_SPEC.md` — єдине джерело істини (фізика, контракти, UI).
- `PLAN.md` — порядок виконання етапів.

**Поточний стан: етап 1** — каркас проєкту та конструктор сутностей.
Фізики, еволюції та аналітики ще немає (етапи 2–5).

## Запуск (Docker)

```bash
docker compose up --build        # UI → http://localhost:8080, API → /api
docker compose down
```

## Запуск без Docker

```bash
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
SERVE_STATIC=1 EVOSIM_DATA_DIR=../experiments uvicorn app.main:app --reload
# UI → http://localhost:8000
```

## Тести

```bash
cd backend
pytest                                  # усі тести
pytest tests/test_schemas.py -k hash    # один тест
```

## Що вже працює (етап 1)

Інтерфейс повністю українською; технічні ключі контрактів показуються
у підказках (`title`) елементів форми.

**Сервер**
- `POST /api/creature/validate` — валідація морфології + `n_joints`, `n_in`,
  `genome_size`, `creature_hash` (§9.1).
- `GET /api/simulation/status` — заглушка `{state:"STOPPED"}`.
- `GET/PUT/DELETE /api/editor/state` — поточна сцена конструктора в
  `experiments/editor/last_session.json`.
- `GET/PUT/GET/DELETE /api/editor/presets[/{name}]` — іменовані варіанти сцен
  у `experiments/editor/presets/`.
- `GET/PUT/GET/DELETE /api/editor/creatures[/{name}]` — бібліотека істот
  у `experiments/editor/creatures/` (морфологія валідується за §9.1).
- `GET/PUT/GET/DELETE /api/editor/predators[/{name}]` — бібліотека хижаків
  у `experiments/editor/predators/` (параметри без маршруту, §8.1).

**Три сутності**

Редактор працює з трьома незалежними сутностями, а симуляція їх поєднує:

| Режим | Що редагується | Де зберігається |
|---|---|---|
| Істота | тіло + кінцівки (морфологія) | `creatures/` |
| Хижак | розмір, швидкості, радіуси | `predators/` |
| Сцена | перешкоди, маршрути патрулювання, точки появи | `presets/` |

**Вкладка «Конструктор»**
- полотно зі світом 60×40, сітка, камера (переміщення правою кнопкою або
  Shift+ЛКМ, масштаб колесом);
- тіло (коло або опуклий полігон), кінцівки (до 6 × до 4 сегментів),
  перешкоди (статичний полігон, статичне коло, рухомий полігон), хижак
  (маршрут патруля + радіуси виявлення/аури/спіймання);
- **діапазони руху суглобів у градусах**: сектор допустимих кутів із
  підписом і привидами сегмента в крайніх положеннях для вибраної кінцівки;
- **мультивибір кінцівок**: `Ctrl/⌘ + клік` (у списку ще `Shift + клік` =
  діапазон), правки застосовуються до всіх вибраних; `Esc` знімає вибір;
- режими **ізольовані**: у «Істоті» на полотні немає ні хижака, ні сцени;
- у сцені все **перетягується мишею**: точки появи, точки маршрутів, перешкоди
  (прилипання до 0.5, `Alt` — вільно);
- **«Сцена»** має підрежими: перешкоди, маршрути патрулювання (до 8 — лише шлях,
  хижака обирають у «Симуляції») і точки появи популяції (до 16 — кілька точок
  дають різні старти епізодів, §7.3);
- **бібліотеки сутностей**: випадаючий список над полотном із мініатюрою та назвою;
  кожна сутність зберігається окремою кнопкою у своїй панелі, поруч видно
  «збережено як …» або «є зміни, не збережені в бібліотеці»;
- **створення нової сутності**: перший рядок кожного списку — «Створити нову
  істоту / нового хижака / нову сцену»; він чистить **лише** цю сутність;
- **варіанти сцен**: збереження під назвою й завантаження назад;
- **Перевірити**, **Зберегти/Завантажити** істоту та сцену окремими JSON,
  **В експеримент**;
- робочий стан (чернетка редактора) зберігається автоматично й відкривається при
  наступному завантаженні сторінки; окремої панелі для цього немає — стан
  автозбереження видно бейджем у шапці, а точки збереження — кнопки в панелях
  самих сутностей.

Активна вкладка й режим редактора тримаються в URL
(`?tab=editor&tool=scene&scene=route`), тож перезавантаження відкриває той
самий екран.

**Вкладка «Симуляція»** — перегляд зібраної сцени на канвасі (істота на точках
появи, хижаки з аурою на маршрутах, перешкоди), попередження на кшталт «старт в
аурі хижака», розмір геному та вартість покоління; вибір істоти, сцени й хижака
зі **збережених** (чернетка редактора в експеримент не потрапляє), форма параметрів ГА і ваг фітнесу, згорнутий `ExperimentConfig` (§9.3).
У конфіг потрапляють копії сутностей, а не назви, щоб прогін лишався
відтворюваним. Кнопки запуску навчання неактивні до етапу 3.

**Живий перегляд (етап 2).** Кнопка **Тест-заплив** запускає епізод у реальному
часі: `POST /api/preview {source:"demo"}` піднімає `World` із контролером-
синусоїдою (§2.4), а кадри йдуть у `/ws/live` зі швидкістю 60 пакетів/с.
Полотно «Симуляції» малює істоту, сегменти, рухомі перешкоди та хижаків з
аурою; камера їде за істотою, темп перемикається множником ×0.25…×4. Та сама
кнопка є в редакторі — там вона бере **чернетку**, не чекаючи збереження в
бібліотеку. Обрив каналу відновлюється сам (0.5 → 8 с), а з черги кадрів
малюється лише найсвіжіший.

## Де лежать дані

```
experiments/editor/last_session.json   # поточна сцена конструктора (поза git: шум автозбереження)
experiments/editor/presets/<назва>.json   # іменовані варіанти сцен (у git)
experiments/editor/creatures/<назва>.json # бібліотека істот (у git)
experiments/editor/predators/<назва>.json # бібліотека хижаків (у git)
experiments/runs/<run_id>/             # прогони ГА (етапи 3–5)
```

Каталог задається змінною `EVOSIM_DATA_DIR` (у Docker — `/app/experiments`,
змонтований том).
