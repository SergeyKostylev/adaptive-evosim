# Етап 4: експерименти з хижаком — журнал для дипломної

Робочий журнал експериментів етапу 4 (хижак, сенсори, повна фітнес-функція).
Усі прогони лежать в `experiments/archive/{run_id}/` (конфіг, `metrics.csv`,
`timing.csv`, найкращий геном, `reaction.json`) і відтворюються побітово в
Docker-середовищі (R7). Сутності — у `experiments/editor/`.

## 1. Постановка

**Мета етапу** (`PLAN.md`, DoD): істоти вчаться виживати — помічати хижака
сенсорами й ухилятися.

- **п.2** — частка спійманих серед топ-10 останнього покоління ≤ 20 %
  (проти ≥ 80 % у поколінні 1);
- **п.3** — на live-прев'ю видно реакцію: істота змінює курс при появі
  хижака в зоні сенсорів.

**Що таке «спіймано серед топ-10».** Частка **епізодів**, а не особин:
10 особин із найвищим фітнесом × `E` епізодів кожна. При `E = 4` це 40
запливів; 80 % = 32 з 40 закінчились спійманням. `caught_all` — те саме по
всій популяції (100 × 4 = 400 епізодів).

**Спільне для прогонів «спиці»:**

| | |
|---|---|
| істота | `swimmer-v1` — 3 кінцівки, 7 суглобів, 55 входів мережі (27 з них — сенсори хижака: 12 променів × канал хижака + 3 аура), геном 1287 ваг |
| сцена | `спиці-4-19`: 3 хижаки на маршрутах-відрізках від r = 4 до r = 19 під 90° / 210° / 330°; 4 точки появи в (0, 0) з кутами 0 / 90° / 180° / 270°; без перешкод; світ 60 × 40 |
| хижак | r_detect 8, аура 5, r_catch 1, патруль 0.5; швидкість погоні — змінна експерименту |
| ГА | 100 особин × 300 поколінь, `E = 4` епізоди по 30 с, елітизм 2, турнір 3, p_mut 0.05, σ 0.15, seed 42 |
| ваги фітнесу | S 3, D 1.5, G_aura 2, C 1, Pas 1, E_n 0.3 |
| обчислення | Docker, 6 процесів оцінки, ≈ 3.4–9 с на покоління |

Чому «спиці»: у першій сцені (`dod4-swimmer`, один хижак на квадраті ±6)
хижака видно з першої секунди, і «пливти прямо» вже частково рятувало. Тут
хижаки приходять з трьох боків, а старти — під чотирма кутами: сліпа
стратегія «прямо» з частини стартів веде просто на маршрут хижака.

Швидкість навченої істоти ≈ 0.8 од/с; тому дефолти хижака змінено з
2.0 / 3.5 на 0.5 / 0.9 (§8.1) — інакше втекти неможливо за будь-якої поведінки.

## 2. Метод перевірки реакції: «зрячий / сліпий»

`python -m app.export.reaction <run_dir>` (`backend/app/export/reaction.py`).

Найкращий геном прогону грає 40 **тестових** епізодів (сіди поза навчальними,
старти по колу) у двох варіантах:

- **зрячий** — геном як є;
- **сліпий** — той самий мозок, але канали хижака (12 променів + 3 аури)
  обнулені.

Сід однаковий, тож до появи хижака в сенсорах обидва варіанти рухаються
**побітово однаково**; будь-яка розбіжність після — реакція саме на хижака
(абляційний тест). Для кожної появи хижака в дальності променів (12 од.)
рахується поворот курсу (1 с до / 2 с після) і косинус між рухом та
напрямком «від хижака». Поворот від хижака — `|Δкурс| > 30°` і косинус зріс.

### 3.1 Погоня 0.9 і 0.7 — навчились плавати, але не ухилятися

- Плавання росте: дистанція `D` найкращої 0.07 → 0.37–0.39.
- Виживання — ні: `caught_all` ≈ 93–96 % від першого до останнього покоління.
- Повільніший хижак (0.7) майже нічого не змінив.
- **Абляція:** зрячий і сліпий поводяться однаково (38 = 38, 39 = 39 спіймань
  із 40; поворотів від хижака 0 і 1). Мережа сенсори хижака **не використовує**.
- Рекордний геном, що в навчанні входив у топ-10 (там ловили «лише» 57–80 %),
  на нових сідах гине в 38–39 з 40 епізодів — **він не найкращий, а найвезучіший**.

## 4. Діагноз і зміна методу: спільні сценарії

**Причина.** Сід епізоду залежав від `(покоління, особина, епізод)` — кожна
особина отримувала **свої** стартові фази хижаків. Хижак біля старту —
майже гарантована смерть незалежно від поведінки, тож фітнес = вміння +
удача, і удача переважала. Турнірний відбір порівнював особини так, ніби
умови однакові, і обирав везучих; вміння ухилятися не накопичувалось.

Побічний ефект: метрика «спіймано серед топ-10» у таких прогонах
**занижена удачею** — у топ потрапляють саме ті, кому дістались легкі
сценарії.

**Зміна** (`ga.shared_scenarios`, `PROJECT_SPEC.md` §6.2, коміт `0334f72`):
сід епізоду — `(run_seed, покоління, епізод)` без особини. Усі 100 особин
покоління проходять **ті самі** 4 сценарії; між поколіннями сценарії
змінюються, тож завчити одну ситуацію неможливо.

У літературі — **метод спільних випадкових чисел** (common random numbers,
CRN), стандартний прийом зменшення дисперсії в симуляційному моделюванні й
стохастичній оптимізації.

Пояснення-аналогія: раніше кожен студент тягнув свій білет, а оцінки
порівнювали як рівні; тепер уся група пише той самий білет, а наступна група
отримує новий.

**Що не змінювали:** фізику, фітнес-функцію, нейромережу, оператори й
параметри ГА, хижака, сцену, істоту, seed. Прогін відрізняється від
`dod4-spokes-v07` **одним прапорцем** — ефект приписується саме йому.
Старші прогони (без поля в конфігу) відтворюються побітово, бо в схемі
прапорець за замовчуванням `false`.

## 5. Результат зі спільними сценаріями

`dod4-spokes-v07-shared__20261029-1325`, середні по 10–20 поколінь:

| покоління | спіймано серед топ-10 | спіймано серед усіх |
|---|---|---|
| 1–20 | 92 % | 97.6 % |
| 61–80 | 94 % | 97.6 % |
| 101–120 | 74 % | 89.8 % |
| 141–160 | 68 % | 83.7 % |
| 191–200 | 42 % | 69.7 % |
| 201–210 | 23 % | 50.6 % |
| 241–250 | 30 % | 52.1 % |
| 291–300 | 23 % | 43.8 % |

- Перші ~100 поколінь — без змін (популяція вчиться плавати), далі
  виживання стабільно росте.
- Поколінь із ≤ 20 % спійманих у топ-10 — 20 (усі після 200-го), зокрема
  останнє: **10 %** (4 з 40 епізодів); у поколінні 207 — 0 %.
- `caught_all` впав із ~97 % до ~50 % — це вміння **всієї популяції**, а не
  кількох везучих (без спільних сценаріїв цей показник за 300 поколінь не
  опускався нижче ~93 %).
- Час покоління зріс 3.7 → 6–9 с — епізоди довшають, бо істоти живуть довше.

Зі спільними сценаріями значення окремого покоління шумніше (важкість
залежить від 4 сценаріїв, що йому дістались: від 0 % до 100 % у сусідніх
поколіннях), тому для критерію п.2 наводимо **і останнє покоління, і
середнє за останні 10–20**.

Прогін — 300 поколінь, 26.8 хв чистого часу на 6 процесах; дистанція `D`
найкращої в останньому поколінні — 0.95 (у прогонах без спільних сценаріїв
0.37–0.39).

**Критерій п.2 формально виконано:** 100 % у поколінні 1 → 10 % в останньому.
Чесніше формулювання для тексту: середнє за останні 10 поколінь — 23 %, за
останні 20 — 31 %; серед усієї популяції — ~44–50 %.

### 5.1 Абляція: що саме навчилась робити популяція

Найкращий геном на 40 нових сценаріях:

| | зрячий | сліпий |
|---|---|---|
| спіймано | **18 / 40** | **20 / 40** |
| середній час життя | 20.0 с | 18.0 с |
| поворотів від хижака після появи | 1 | 1 |

- Порівняно з попередніми прогонами (38–39 / 40) — **реальне вміння, що
  переноситься на нові сценарії**, а не удача.
- Але сліпий виживає майже так само, як зрячий: перевага сенсорів хижака —
  2 епізоди з 40, у межах шуму. Реакції на появу хижака (п.3) немає.

**Що ж тоді виживає?** Кінцеві положення вцілілих (кут від старту):

- зрячий — 119°…157° (22 з 22 вцілілих);
- сліпий — 133°…157° (20 з 20).

Тобто з **будь-якого** з чотирьох стартових кутів істота розвертається й
пливе в сектор ≈ 120–160°. Це якраз проміжок між спицями хижаків на 90° і
210° (його середина — 150°), найдальший від маршрутів. Орієнтуватися їй
дозволяє пропріоцепція: серед входів мережі є `sin` і `cos` кута власного
тіла — фактично **компас**. Популяція вивчила «карту» цієї сцени: «пливи на
150°», і для цього сенсори хижака не потрібні.

Це законна адаптація (еволюція знаходить найдешевше рішення), але не та
поведінка, яку перевіряє п.3: реакцію на хижака тут не винагороджено, бо
безпечний напрямок у сцені **фіксований**.

## 6. Висновки для тексту

1. Механізми етапу (хижак, сенсори, повна фітнес-функція) працюють і
   покриті тестами; Headless ↔ Live не ламає навчання (просідання 9 %).
2. Зміна параметрів задачі (сцена, швидкість хижака) **не** дала ухиляння:
   абляція показала, що сенсори хижака мережею не використовуються.
3. Причина — у методі оцінювання: індивідуальні випадкові сценарії робили
   відбір відбором за удачею. Спільні сценарії в поколінні (CRN) — одна
   зміна — запустили навчання виживання: частка спійманих серед топ-10
   100 % → 10 % (середнє ост. 20 поколінь 31 %), і вміння переноситься на
   нові сценарії (18 / 40 проти 38–39 / 40).
4. Абляція показала, **як** популяція виживає: не реагує на хижака, а
   запам'ятовує безпечний напрямок сцени за «компасом» власної орієнтації.
   Еволюція знаходить найдешевше рішення; щоб отримати реакцію на хижака,
   середовище має робити її **необхідною** (безпечний напрямок не повинен
   бути фіксованим).
5. Методичні уроки: (а) метрика «частка спійманих серед найкращих» без
   спільних сценаріїв зміщена удачею — порівнювати особини слід на однакових
   реалізаціях випадковості; (б) зниження частки спійманих саме по собі не
   доводить використання сенсорів — потрібна абляція «зрячий / сліпий».

## 7. Обмеження й подальша робота

- **Рекорд прогону зміщений легкими поколіннями.** `best_genome.json` (і кнопка
  «Найкраща особина») — особина з найвищим фітнесом за **весь** прогін. Зі
  спільними сценаріями покоління порівнюються на різних сценаріях, тож рекорд
  потрапляє в найлегше покоління: у `dod4-spokes-v07-shared` рекорд F = 4.14 —
  з покоління 268, де спіймали лише 11.5 % усієї популяції (типово 44–50 %).
  Це та сама проблема «удачі», лише між поколіннями. Абляція §5.1 зроблена
  саме на цьому геномі (і все одно дала 18 / 40). Коректніше обирати чемпіона
  переоцінкою кандидатів (найкращих кількох останніх поколінь) на
  **фіксованому** наборі тестових сценаріїв.

- **Наступний крок для п.3:** прибрати фіксований безпечний напрямок —
  наприклад, випадковий поворот усієї сцени (маршрутів хижаків) на епізод
  або випадкові точки появи. Тоді «карта» не працює, і виживання вимагає
  дивитися на хижака. Альтернатива — прибрати з входів абсолютну орієнтацію
  тіла (компас). Обидва — зміни постановки, їх треба вносити в специфікацію
  як окремий експеримент.

- Окреме покоління зі спільними сценаріями шумне; для оцінки варто
  перевіряти найкращу особину на фіксованому наборі тестових сценаріїв.
- Фітнес нагороджує результат (вижив / ні, час в аурі), а не саму реакцію;
  нагорода за збільшення відстані до видимого хижака — можлива наступна
  гіпотеза.
- Навчання «від простого до складного» (curriculum: один повільний хижак →
  три) не перевірялось.
- Обчислювальна деталь: на macOS Docker-прогін зупиняється, коли машина
  засинає; для довгих прогонів — `caffeinate` і живлення від мережі.
